# 劳动争议案件全流程工作流

## 概述

本技能将劳动争议案件处理固化为八步流水线，已在多起真实案件（深圳地区，用人单位侧）中跑通验证。核心链路：**案情输入（OCR 数字化）→ 法律推理（争议焦点）→ 法条检索（元典，含效力核验）→ 类案研究 → 策略分析 → 文书生成（三件套）→ 证据三性质证 → 期限管理与复盘入库**。

## 前置条件检查

开工前确认以下环境，缺失则先修复：

1. **连接器**：yuandian-mcp（元典法条/案例检索）= connected；ima-mcp（知识库）= connected；cn-legal（mcp.json 中已配置，需用户在连接器页点"信任"后 `mcp__cn-legal__*` 可用）。
2. **Python 隔离环境**：使用托管 Python（绝对路径），venv 中需有 `pypdfium2`（PDF 渲染）、`python-docx`（文书生成）、`cos-python-sdk-v5`（ima 上传）。包一律装入 venv，禁止全局安装。
3. **Windows 环境坑**：WorkBuddy 注入的 `NODE_OPTIONS` safe-delete 补丁会导致 pnpm/npm 失败——一律 `env -u NODE_OPTIONS` 前缀运行（详见 win-node-safe-delete-fix 技能）。
4. **本地 docx 读取坑**：editor_sdk（edsdk.py）打开 docx 后 `doc_get_document_content` 可能持续报 "document is not open"——重试无果后按路由技能回退规则改用 `scripts/extract_docx_text.py` 直接解包提取，并告知用户。

## 八步工作流

### Step 1 案情输入与材料数字化

目标：把全部案件材料转为可读文本/图片，建立案件工作区。

- 扫描版 PDF（无文本层）：用 `scripts/render_pdf_pages.py` 逐页渲染为 PNG（scale=2.0），再用多模态 Read 视觉识读（效果等同 OCR）。逐批识读并即时记录要点。
- docx：优先按 tencent-docs-routing 技能走 editor_sdk；失败则回退 `scripts/extract_docx_text.py`（解包 XML 提取正文，支持 .docx/.doc/.txt 批量）。
- 图片证据（聊天截图等）：直接 Read 视觉识读，按时间线登记：时间、对话双方、关键表述、对哪方有利。
- 输出：案件事实清单 + 证据台账（名称/来源/形式/拟证明事实/有利方）。

### Step 2 法律推理与争议焦点识别

- 调用 `mcp__cn-legal__cn_legal_think` 做领域识别与核心争议点初判（劳动争议领域）。
- 配合原子技能：structured-element-extraction（要素提取）→ dispute-issue-identification（争议焦点识别）→ argument-chain-construction（组织论证链，预防性+备选结构）。
- 输出：争议焦点清单，每个焦点标注请求权基础、举证责任归属（解释一第44条：减少劳动报酬/解除决定由单位举证）、初步胜负判断。

### Step 3 法条检索与效力核验（元典）

- 工具组合：`yuandian_rh_ft_search`（法条关键词）→ `yuandian_rh_fg_search`（法规列表）→ `yuandian_rh_fg_detail`（按 id 取全文）→ `yuandian_law_vector_search`（语义检索交叉验证）。
- **必须核验效力状态（sxx 字段）**：现行有效/部分失效/失效。已知坑：解释（一）部分失效（32条1款废止）；粤高法〔2017〕147号已失效；fgmc 过滤对全角/半角括号敏感。
- 深圳地区核心口径已沉淀在 `references/shenzhen-labor-rules.md`——先读它，再按需补查。
- ⚠️ 不得凭记忆写法条号和内容；引用前必须经数据库核验（张颜案教训：用户提供的"深圳裁判口径要求催告"与指引第82条字面相反，原样写入会被仲裁员当场反噬）。
- ⚠️ **元典不可用时的降级核验路径（2026-09-09 实测）**：连接器状态可能显示 `yuandian-mcp: connected`，但 ToolSearch 查不到任何 `yuandian_*` 工具（deferred tools 列表无此项）。此时不要卡住，改走 `mcp__doubao-search__web_search`，参数 `authLevel: 1`（只要权威源）+ `count: 5~8`。
  来源优先级：国家法律法规数据库 flk.npc.gov.cn（可直接看"有效/失效"）> 中国政府网 gov.cn > 人社部 mohrss.gov.cn > 最高人民法院公报 gongbao.court.gov.cn > 中国法院网 chinacourt.cn > 省高院/中院官网。
  判例与裁判口径：同一工具不限 authLevel，优先找"XX中院/XX法院 + 具体案号"，自媒体转述须交叉验证两条以上。
  降级核验同样满足上述铁律——**只要求来源权威、效力可查，不强制用哪个库**。

### Step 4 类案研究

- 用 `yuandian_case_vector_search` 做类案语义检索，配合 case-retrieval 原子技能整理裁判要旨。
- 重点检索：同地区（深圳/广东）、同争议类型（被迫解除/绩效扣款/交接赔偿）的裁判倾向，用于校准策略报告的胜率评估。

### Step 5 策略分析报告

输出 Markdown 策略报告，固定章节：①案件基本情况与请求金额拆解表；②事实时间线（精确到日，标注证据出处）；③争议焦点逐项法律分析（大前提-小前提-结论，标注置信度）；④双方风险评级表（必输项/争议项/可放项）；⑤抗辩策略与证据组织建议；⑥和解区间测算（必输项+争议项 50%-70%）与和解协议关键条款；⑦程序要点（期限、出庭人员、质证重点）；⑧HR/管理层操作风险提示。
- 报告必须含免责声明（辅助分析，非正式法律意见，建议委托执业律师）。

> #### ⛔ Step 5 金额测算铁律（张颜案 V1 翻车教训，必读）
>
> **任何写进报告的金额结论，必须跑数实测，禁止凭印象估算。**
>
> 张颜案 V1 报告写"经济补偿 30,000 元有 60%–70% 概率压到 15,000–25,000 元"，
> 实测工资表后真相是 **27,071 元，压低空间仅 2,929 元**。
> 该错误直接导致整套和解让步方案（"压到 18,000–20,000 元"）不可执行，
> 若写进和解协议草案被对方看到，反而暴露我方测算不实。V2 才纠正过来。
>
> 硬性动作：
> 1. **先拿原始工资表 xlsx，不要只看工资条截图或当事人转述。**
>    用 `scripts/calc_econ_comp_base.py` 核算经济补偿基数（自动定位列、合并同月多行、标注需人工核对的月份、输出封顶校验）。
> 2. **用 `openpyxl` 逐列核对工资表结构**，重点看三类隐藏信息：
>    - 「其他扣款 / 乐捐 / 财务扣款」列 → 可能坐实"罚款"事实，也可能证明赔偿款已扣（反申请构成重复救济，须改备位请求）；
>    - 「绩效得分 / 应发比例」列 → 可能推翻"未考核"的抗辩前提（张颜案 6 月绩效实为已考核、按 0.5 发放）；
>    - 是否存在对方主张的工资科目（张颜案"年度绩效池 600 元/月留存"在工资表中根本无此列 → 该项抗辩胜率由 20% 升到 50%）。
> 3. **识别请求项之间的重叠**。同一笔钱常被对方拆成两个请求表述（如"5月工资差额"与"5月绩效"），
>    核算最大敞口时**必须去重**，否则会严重高估风险、误导和解定价。
> 4. **输出三情景**（基准 / 部分主张被认定违法 / 全部被认定违法），
>    因为胜诉争议本身会改变工资基数，单点估值没有意义。
> 5. 报告更新时**附 V1→V2 修订对照表**，把被推翻的判断明确标为"作废"，
>    并点名作废的谈判表述，避免旧版文件仍在内部流转造成误用。

### Step 6 文书生成（三件套）

用 `scripts/gen_legal_docx.py`（公文格式封装类 LegalDoc）生成，勿手写格式代码：

| 文书 | 时机 | 要点 |
|------|------|------|
| 答辩状+证据清单 | 收到副本起 **10 个工作日内** | 论证结构见 `references/defense-playbook.md` 第二节 |
| 反申请书+证据清单 | 同答辩期 | 劳动仲裁称"反申请"非"反诉"；请求须具体可执行（返还设备/赔偿确定金额），损失证据不足时写"保留另案主张" |
| 质证意见书 | 开庭日 | 严格按对方证据清单逐项编号对应；话术见手册第三节 |
| **庭审发言指引**＋**出庭执行清单** | 开庭前 1 日 | 指引按庭审全流程分阶段给话术（庭前准备／核对身份与回避／答辩陈述／调查／举证质证／发问应答／辩论／最后陈述／调解／庭后），每阶段含"要点＋可直接照读示例＋禁忌＋突发应对"；执行清单补出庭人专项话术、授权委托书、出发前检查表。**定稿文书必须先按手册第八节回查实际 docx 再打印** |

- 所有事实性占位（收到副本日期、付款日期、金额）用【 】标出并在交付时逐项提醒用户填写。
- 金额必须复算（各项合计=对方请求总额；日工资=月工资/21.75）。
- 劳动仲裁不收费，不写"仲裁费由对方承担"。

### Step 7 证据三性分析与质证

- 调用 evidence-evaluation 原子技能框架：真实性（形式/内容两层切割）、合法性（主体/程序/形式）、关联性（直接/间接）+ 证明力评级（★1-5）。
- 公司侧通用策略：认真实性不认证明目的；解除通知书只认送达事实；单方制作材料不认可；电子数据截图要求当庭出示原始载体。
- 同时输出己方证据加固清单（如考勤记录需带系统时间戳+OA审批流原件）。

### Step 8 期限管理与复盘入库

- 接案第一件事：从开庭应诉通知书签发日/副本签收日推算答辩期（10 个工作日），向用户高亮倒计时。
- 案件办结：答辩状等文书经 `scripts/cos_upload_sdk.py` 流程入 ima 知识库（create_media 取 COS 临时凭据 → SDK put_object → add_knowledge；手写 COS 签名会报 "Request has expired"，必须用官方 SDK）。
- 新裁判口径/新打法 → 更新两个 references 文件；项目事实 → 更新工作区 memory。

## 变体流程：用人单位主动追偿类案件（社保补缴垫付追讨等）

当公司是**主动方/债权人**（如补缴社保后向离职员工追讨个人应缴部分），不适用仲裁三件套，按民事追偿路径走（朱懋春案已验证）：

1. **定性**：员工已离职 → 不当得利/委托合同民事案由，**无劳动仲裁前置**；在职员工追讨垫付款仍属劳动争议。
2. **核心法律点**：个人部分本金全额可追（社保法第60条+深圳类案：盛音达案/谷某辉案/精工伟达案）；**滞纳金不得转嫁员工**（人社部令第20号第20条）；**利息/违约金无书面约定则败**——催告函中只写"保留主张权利"，勿单方设定费率。
3. **文书组合（替代三件套）**：①《催告函》（EMS多址齐发+面单注明文件名+微信同步，送达即中断时效）；②《还款确认书》（无异议条款封死金额异议 + 万分之五/日违约金条款"有约定即支持" + 送达地址 + 管辖条款）；③《支付令申请书》（催告后首选司法动作，受理费约1/3，被异议自动转诉讼零程序损失，**不能公告送达**——失联者直接起诉）。
4. **升级顺序**：电话录音跟催→书面确认→催告函→律师函→支付令/小额诉讼（一审终审）。触发信号：催告期满7日未付/失联≥2周/明确拒付/转移财产。
5. 事实性占位同样用【 】标注；金额复算（单位+个人=补缴总额）。

## 资源索引

- `scripts/render_pdf_pages.py` — 扫描 PDF 分页渲染 PNG（OCR 前置）
- `scripts/extract_docx_text.py` — docx/doc/txt 正文直提（editor_sdk 失败时的回退）
- `scripts/docx_replace_text.py` — docx 精确文本替换（**跨 run 匹配**，支持正文+表格，可一次传多组替换对；**不覆盖原文件**，输出路径必须不同于输入）。用于定稿改稿：`python docx_replace_text.py 原版.docx 定稿版.docx "旧" "新"`
- `scripts/gen_legal_docx.py` — 法律文书生成器（公文格式 LegalDoc 类：标题/当事人/分级标题/正文/落款/证据清单表）
- `scripts/calc_econ_comp_base.py` — 经济补偿基数核算器（读工资表 xlsx，算解除前12个月平均应得工资 ×N，含封顶校验与复核清单；`--list-sheets` 先探表头）
- `scripts/md2docx.py` — Markdown 分析报告一键转公文格式 docx（支持 `#/##/###` 三级标题、表格、引用块、列表、行内 `**粗体**`；自动把 🔴🟡🟢⚠️ 转为【高危】【中】【有利】【注意】文字标记）。用法：`python md2docx.py 输入.md 输出.docx`
- `scripts/cos_upload_sdk.py` — ima 知识库上传（官方 COS SDK 版）
- `references/shenzhen-labor-rules.md` — 深圳劳动争议核心裁判口径（逐条经元典核验，含效力状态与用法提示）
- `references/defense-playbook.md` — 用人单位侧答辩打法手册（三件套结构、质证话术、制度硬伤自查清单、和解策略、期限红线）
