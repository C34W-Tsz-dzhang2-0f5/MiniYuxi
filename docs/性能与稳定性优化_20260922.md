# MiniYuxi 性能与稳定性优化（2026-09-22）

> 方法：用 huashu-chrome 真实浏览器驱动 + API 批量探活，对 MiniYuxi 做功能/性能/结构体检，
> 锁定 5 个具体、可量化、低风险的优化点并落地。优化后 `python -m pytest tests/test_hermes_landing.py` 13 passed、
> `python tests/selftest.py` 20/20 通过，真实浏览器对话链路（登录→问答→引用）端到端可用。

## 一、体检结论（优化前）

| 项目 | 结果 |
|---|---|
| 启动方式 | `python run.py --port 8801`（FastAPI + 原生 uvicorn，单进程） |
| 模块冷启动导入 | `import api` 一次性 eager 导入约 50 个 core 模块，耗时 **2.6s** |
| 核心端点可达性 | 14 个核心端点全部 200（仅 `kb/search` 误用 GET 返回 405，属测试写法问题，非缺陷） |
| 对话链路 | `/api/wb/chat` 端到端通：模型路由→RAG→带引用中文回答（~1.3–1.9s，含真实 LLM 调用） |
| DB 并发韧性 | `db.connect()` 仅设 WAL + foreign_keys，**无 `busy_timeout`/`synchronous`/`cache_size`** |
| 热点端点延迟 | `tools/list` 0.263s、`skills/list` 0.035s、`workbench` 0.032s、`health` 每次做网络探测 |

## 二、优化点（已落地）

### O1 · DB 并发与性能韧性（稳定性，高优先）
- **文件**：`core/db.py` `connect()`
- **问题**：两进程共用同一 SQLite 文件（如 8801 与测试实例 8802）时，并发写极易 `database is locked`；缺少页缓存放大。
- **改动**：在 WAL 基础上追加
  `PRAGMA busy_timeout=5000`（写冲突等待而非立即报错）、
  `PRAGMA synchronous=NORMAL`（WAL 下仍崩溃一致且写入更快）、
  `PRAGMA cache_size=-16000`（16MB 页缓存）、
  `PRAGMA temp_store=MEMORY`。
- **验证**：`PRAGMA busy_timeout=5000 / synchronous=1 / cache_size=-16000 / journal_mode=wal / temp_store=2` 全部生效。

### O2 · `/api/tools/list` MCP 探测缓存（效率）
- **文件**：`core/tools_registry.py` `list_tools()`
- **问题**：每次调用都 `mcp_client.discover_tools()` 做外部网络探测，UI 加载必调 → 0.263s。
- **改动**：对 MCP 发现结果加 **60s TTL** 内存缓存。
- **效果**：0.263s → **0.007s**（~38×）。

### O3 · `/api/skills/list` 目录扫描缓存（效率）
- **文件**：`core/skills_catalog.py` `list_skills()`
- **问题**：每次 `glob` 递归扫 `skills/**/SKILL.md`。
- **改动**：按 `skills/` 目录 mtime 缓存，未变动则直接返回上次结果。
- **效果**：0.035s → **0.008s**（~4.5×）。

### O4 · `/api/health` 后端探测缓存（稳定性 + 效率）
- **文件**：`core/tools_registry.py` `search_backend_status()`
- **问题**：`/api/health` 是热端点，每次真实探测豆包(火山引擎)可达性，网络超时可达 4s，会阻塞健康检查/前端轮询。
- **改动**：探测结果加 **30s TTL** 缓存，health 瞬时返回。
- **效果**：health 稳定 ~0.005s，且豆包不可达时不再拖垮健康检查。

### O5 · `GET /` 首页渲染缓存（效率）
- **文件**：`api.py` `index()`
- **问题**：每个请求都读 `index.html` 并做 `__ICONS_JSON__` 字符串替换。
- **改动**：按文件 mtime 缓存渲染结果（图标 JSON 本身已缓存）。
- **效果**：首页重复访问零文件 I/O。
