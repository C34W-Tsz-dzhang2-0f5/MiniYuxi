# ADR-0001: MiniYuxi 生产边界 — 桌面优先，八要素分表面定边界

- **状态**：已采纳（Accepted）
- **日期**：2026-09-29
- **决策人**：阿长（产品定位）/ 助理（落盘）
- **关联**：`docs/enterprise-boundary-desktop-web-20260929.md`、`docs/企业级合规与架构边界说明.md`（2026-09-14，部分被本 ADR 重框）

## 背景

- 2026-09-14 的《企业级合规与架构边界说明》默认 MiniYuxi 是「多租户 SaaS + 对外高并发 HA」形态，把多租户隔离/负载均衡/读写分离当成普遍硬约束。
- 但阿长 2026-09-24 更正产品定位为 **企业级 Agent · 零 Docker · 数据可出本机 · 可商用**——实际是**桌面优先**产品。
- `enterprise-agent-scaffolding` 的八要素若一刀切套云 SaaS，会对桌面版产生大量 **➖ 不适用** 的无效约束，反而稀释真正要卡的生产边界。

## 决策

1. **桌面优先**：MiniYuxi 第一形态是桌面版（Tauri，本机单用户单进程，天然单租户）。网页版复用 `web/`，可本机跑也可对外部署。
2. **八要素分表面定边界**：对 桌面版 / 网页版（对外多租户）/ 共用 core 三表面分别标注 ✅/🟡/🔴/➖。
   - 桌面版：① 多租户隔离 ➖ N/A；④ 可观测性、⑤ 成本硬熔断为 🔴 真缺口；③ 审计、⑥ HITL 已 ✅。
   - 网页版对外部署：在桌面版门禁上叠加 ① 多租户数据层隔离、② RBAC、④ 可观测面板、⑧ canary。
3. **保留旧文档的"代码控制点 vs 外部依赖"结论**：等保三级 / ISO 27001 / CMK / HA 的证书与基础设施仍须外部，任何代码替代不了。

## 后果

- 桌面版上生产的硬门禁收敛为：③ 审计（SOC 哈希链）、⑤ 成本硬熔断、⑥ HITL、商用授权（零 copyleft）、MSI 干净装机验证。
- "多租户隔离 / 对外 HA" 不再作为桌面版发布阻塞项。
- 后续工单拆分（to-spec/to-tickets）以「④ 可观测性 trace_id 贯穿」「⑤ 成本硬熔断」为第一批 tracer-bullet。

## 可逆性

- 若将来 MiniYuxi 明确以"网页版对外多租户 SaaS"为主形态，本 ADR 需重开，将 ①/②/④/⑧ 升级为普遍硬门禁。
