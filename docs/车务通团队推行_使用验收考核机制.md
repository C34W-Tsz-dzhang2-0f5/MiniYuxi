# 车务通团队推行 · 使用 / 验收 / 考核机制

> 配套《MiniYuxi 360 七坑审查》三项 🟡 整改（PR 卡点、法条硬闸门、散落归仓）。
> 本文档用于把"个人能跑通"升级为"团队可复制、可验收、可追责"。
> 适用范围：车务通（深圳）前台 / HR 兼案件代理岗；母公司的使用与车务通同口径。

---

## 一、使用机制（怎么用才不出事）

1. **知识库先行，禁止空库问法条**
   - 任何劳动/法律类问答前，必须先把相关法规、制度、裁判口径原文上传至知识库。
   - 平台已对法律/劳动类问题启用「无引用不出文」硬闸门（`core/citation_gate.py`）：
     未命中知识库、或答案编造知识库中不存在的法规名时，系统**直接拒绝生成**，
     强制先补原文或核验来源。这是平台级护栏，不是建议。
2. **法条必核验，不凭印象**
   - 引用《xxx法/条例》必须来自知识库命中或用户已确认的来源；
   - 已废止法律（民法通则、合同法、物权法等）一律以《民法典》对应编替代，引用前查效力。
3. **本地优先、回环登录**
   - 局域网 IP 访问时 LAN 守卫会把默认口令重置为随机串，登录信息看启动日志或回环地址登录；
   - 不要在非受控网络暴露 admin 口令。
4. **改前端必须过验证**
   - 任何前端改动提交前跑 `bash scripts/verify-precommit.sh`（未定义符号扫描 + 法条闸门单测）；
   - 推送到 `main` / 开 PR 由 GitHub Actions（`.github/workflows/verify.yml`）自动卡点 + 路由冒烟，未过即阻断合并。

---

## 二、验收机制（怎么算交付合格）

| 验收项 | 标准 | 卡点/证据 |
|---|---|---|
| 前端改动 | 路由冒烟 40 项全绿、未定义符号扫描 0 误报 | `tests/_smoke_routes.py`、`tests/_scan_undef.py` 退出码 0 |
| 法条生成 | 法律/劳动问答均有知识库引用，无编造法规 | `tests/_verify_citation_gate.py` 10/10；空库法律问题返回 `mode=citation_blocked` |
| 核心能力 | 端到端自检 20/20 | `python tests/selftest.py` 全 PASS |
| 知识库 | 上传法规/制度后检索可命中、租户隔离 | 自检"多租户数据隔离"项 |

验收动作：每次合并前 CI 必须全绿；重大改动追加一条回归用例进 `tests/`。

---

## 三、考核机制（谁负责、怎么追责）

1. **责任人**：MiniYuxi 维护归阿长（HR 兼案件代理），代码护栏归维护人；
   母公司与车务通共用同一仓库与同一套卡点，不做私有 fork。
2. **红线（一票否）**：
   - 用 `--no-verify` 跳过 pre-commit 卡点合并代码；
   - 在空知识库状态下向外输出"法条结论"；
   - 把 admin 口令暴露在公网。
3. **复盘**：每次"无法对话 / 回答编造 / 卡点被绕过"类事故，先查 `tests/` 是否缺对应回归用例，
   缺则补用例后再修代码（堵坑3 复发路径）。
4. **经验固化**：踩坑即写进 `~/.workbuddy` 技能或本仓库 `docs/`，不依赖个人记忆；
   新成员按本文档"使用机制"上手，按"验收机制"交付。

---

## 四、与 360 七坑的对应

- 坑3 一键生成 → 已用 `_scan_undef.py` + `_smoke_routes.py` + CI 卡点封死复发；
- 坑2 裸奔/编造 → 已用 `core/citation_gate.py`「无引用不出文」硬闸门封死；
- 坑4 孤岛 → 验证脚本/截图/日志已归仓 `tests/`、`docs/_shots`、`docs/_archive`，根目录只留应用与运维脚本；
- 坑7 惯性 → 本文档把"个人打法"固化为团队可复制的使用/验收/考核机制。
