# MiniYuxi 前端界面体验审计报告

- **审计对象**：MiniYuxi 智能工作台前端
  - 入口页：`web/index.html`（根路由 `/`，MiniYuxi 文字标，当前主界面）
  - 组件：`web/wb_workbench.{html,css,js}`（复刻 WorkBuddy 三栏式工作台）
  - 图标：`web/wb_icons.json`；注入逻辑：`api.py` 的 `__ICONS_JSON__` 替换
  - 对照入口：`/wb`（wb_workbench.html，WorkBuddy 皮肤）、`/legacy`（index_legacy.html，旧版皮肤）
- **审计方法**：静态代码审计 + 交互逻辑走查 + 前端设计原则评估（不依赖运行时截图，结论均可在源码定位）
- **审计维度**：① 视觉美观度 ② 使用便捷性 ③ 布局与交互合理性
- **严重度定义**：
  - 🔴 **P0 严重**：破坏产品可信度 / 安全性 / 核心可用性，必须修复
  - 🟡 **P1 重要**：明显影响体验或可用性，应优先修复
  - 🟢 **P2 一般**：细节打磨，建议优化

---

## 一、总体结论（结论先行）

**界面已完成 WorkBuddy 风格的"专业级"复刻**，三栏骨架、主题切换、流式回复、多模型路由均已跑通，基础体验达标。但当前处于 **"可用但未打磨"** 阶段，存在 **3 处硬伤（P0）+ 多项便捷性缺口**：

| 维度 | 评级 | 核心问题概述 | 主要缺口数 |
|------|------|-------------|-----------|
| 视觉美观度 | **B（良好）** | 复刻到位，但品牌割裂、假数据、图标缺口 | P0×1 / P1×3 / P2×3 |
| 使用便捷性 | **C+（偏弱）** | 默认 admin 静默登录、会话/概览为假数据、无消息操作 | P0×2 / P1×5 / P2×2 |
| 布局与交互合理性 | **B-（尚可）** | 断点过激砍功能、首屏不暴露多模型、双输入冗余 | P0×0 / P1×4 / P2×3 |

> 一句话：**"好看但不可信、好用但别扭"** —— 视觉可打 80 分，体验与可信度拖后腿。建议优先处理 P0（3 项），再按路线图收口 P1。

## 三、使用便捷性

| # | 问题 | 严重度 | 具体表现 | 影响范围 | 改进方向 |
|---|------|--------|---------|---------|---------|
| U1 | **默认静默 admin 登录（安全/信任硬伤）** | 🔴 P0 | `ensureToken()` 无 token 时自动 `login('default','admin','admin123')`；任何人打开即获 admin 权限，"登录"形同虚设 | 全部用户、本地与部署环境 | 取消默认账号自动登录；未登录时显式引导登录；默认账号仅作首次初始化，强制改密；LAN 部署强制口令（已有 `run.py` 守卫，需与前端登录态联动） |
| U2 | **会话列表为硬编码假数据** | 🔴 P0 | `CONVERSATIONS` 写死 6 条；"新建对话"不新增列表项，搜索仅在这 6 条内过滤；刷新即丢失 | 会话管理核心路径 | 接 `/api/wb/chat` 的真实会话列表（或 localStorage 持久化草稿）；新建/切换/删除实时同步 |
| U3 | **"登录"按钮无状态反馈** | 🟡 P1 | 右上角始终显示"登录"，但 init 已静默登录；点开预填 admin/admin123，用户搞不清"我到底登没登" | 全局认知 | 已登录显示"用户名/登出"，未登录显示"登录"；footer 头像同步真实身份 |
| U4 | **快捷入口点击仅填框不发送** | 🟡 P1 | `renderQuickActions` 点击把"帮我完成「X」："填入输入框，需再按回车；多数用户预期"点即发起" | 首屏转化、上手效率 | 提供"点击即发送"主行为 + 长按需编辑；或按钮文案明确"点击填入" |
| U5 | **"技能"抽屉语义误导** | 🟡 P1 | 文件夹技能（如 P0 移植的劳动关系待办）被当作 `/指令` 插入（`insertAtCursor('/'+title+' ')`），但 folder 技能非 `/` 触发式，发送后可能无效 | 技能调用成功率 | 区分"指令型技能（/触发）"与"能力型技能（注入 system prompt）"，后者应走 `load_skill` 注入而非 `/文本` |
| U6 | **多模型"对比"多选方式隐蔽** | 🟡 P1 | 需 Ctrl/⌘ 点击卡片加入对比，提示仅模型中心底部一行小字；用户很难发现 | 多模型高级能力使用率 | 显式"加入对比"勾选框/按钮；或在卡片加对比态徽标 |
| U7 | **消息无操作条（复制/重试/删除）** | 🟡 P1 | 每条 msg 仅显示时间，无 hover 操作；用户无法复制 AI 回答、删除误发、重试失败回复 | 对话续航、内容复用 | 悬浮操作条：复制 / 重新生成 / 删除；失败态加"重试" |
| U8 | **Markdown/代码不渲染（纯文本）** | 🟡 P1 | `addMessage`/`streamBubble` 用 `textContent`，代码块、列表、表格全为纯文本，无高亮换行 | "代码开发/深度研究"场景可读性（技术&HR 文档均受影响） | 引入轻量 Markdown 渲染（如 `marked` + 代码高亮 `highlight.js`），AI 气泡用 `innerHTML` 安全渲染（先转义再解析） |
| U9 | **附件失败无重试/移除** | 🟢 P2 | `renderRefList` 显示"文件名·失败"但无删除/重试入口；只能刷新清空 | 文件引用体验 | ref chip 加 `×` 移除；失败态可点击重试上传 |
| U10 | **无全局命令面板（⌘K）** | 🟢 P2 | 全部依赖鼠标点 9 项 nav + 工具面板，无键盘快捷操作 | 高频用户效率 | 增加 ⌘K / Ctrl+K 命令面板，聚合"新建/切换模型/调技能/搜会话" |

## 四、布局与交互合理性

| # | 问题 | 严重度 | 具体表现 | 影响范围 | 改进方向 |
|---|------|--------|---------|---------|---------|
| L1 | **≤1024px 直接砍掉右侧整栏** | 🟡 P1 | `@media(max-width:1024px){.detail-panel-container{display:none}}`；"概览/产物/引用来源"完全消失且无替代入口（如抽屉） | 平板、小窗口用户 | 改为可滑出抽屉（右侧面板 → 浮层），保留功能可达性 |
| L2 | **顶部 nav 隐藏无"更多"溢出** | 🟡 P1 | `1024px` 隐藏第 5+ 项，`768px` 整条隐藏；"成本管理/工作台/管理/岗位工作台"凭空消失 | 中屏用户功能可达性 | nav 超出时折叠为"⋯更多"菜单；或改为可横向滚动 |
| L3 | **多模型路由条首屏不暴露** | 🟡 P1 | `mx-bar` 仅在对话态 `chatDock` 显示；欢迎态看不到"工作台/自动/对比"，首条发出后才发现该能力 | 多模型能力发现成本 | 欢迎态输入框下方常驻一行精简模型模式入口，或首屏场景区旁加模式切换 |
| L4 | **"允许完全访问"默认开 + 弱提示** | 🟡 P1 | `state.allowFullAccess=true` 且工具面板内默认勾选；切换仅 toast 提示，普通用户不理解含义 | 安全边界（尤其 LAN 部署） | 默认改为"受限"；开启时弹一次明确风险说明；与 U1 登录守卫联动 |
| L5 | **双输入框冗余逻辑** | 🟢 P2 | 欢迎态 `composerInput` 与对话态 `composerInputDock` 两套 contenteditable，各自绑定事件、`syncSend` 双判；易状态不同步 | 维护成本、潜在 bug | 统一为单输入框 + 视图切换，减少分支 |
| L6 | **移动端工具按钮只剩符号** | 🟢 P2 | `@media(max-width:768px)` 隐藏 `.composer-tool span:not(.tool-kbd)`，`@ 引用对话文件` 退化为孤立 `@` 符号，可发现性差 | 移动端 | 保留图标 + 短标签，或点击展开工具浮层 |
| L7 | **二级面板互斥无整合** | 🟢 P2 | "引用来源"面板 `position:absolute;inset:0` 覆盖整个右侧，打开即看不到"概览"；两者无 tab 共存 | 信息并行查看 | 来源并入右侧 tab 体系（已有概览/产物/模型任务，加"来源"tab 即可），去掉覆盖式浮层 |
| L8 | **流式渲染用 setInterval 重设 textContent** | 🟢 P2 | 每 16ms 重设整段 `textContent`，长文（数千字）频繁重排，无增量/RAF 优化 | 长回复性能 | 改用 `requestAnimationFrame` 增量追加 + 文档片段，降低重排 |
